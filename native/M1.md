# Spike QCAD CE — 2026-10-09

Build local Windows aprobado del commit auditado, con un parche CMake original de
cuatro líneas. Compilador MSVC 19.50.35728 / Build Tools 2026; Qt 6.10.3
msvc2022_64; CMake 4.1.3 y Ninja 1.13.0. El SDK queda en .cache del proyecto;
sin plugins comerciales, instalación global ni cambio de protecciones.

## Reproducir

En Windows con Visual Studio Build Tools C++ x64, Python 3.12 y fuente fijada:

```powershell
python -m pip install -e . aqtinstall==3.3.0 cmake==4.1.3 ninja==1.13.0
python -m aqt install-qt windows desktop 6.10.3 win64_msvc2022_64 --outputdir .cache/qt --archives qtbase qtdeclarative qtsvg qttools
./tools/build_qcad.ps1
ctest --test-dir build/native --output-on-failure
```

Clonar QCAD en `.cache/upstream/qcad` y hacer checkout del SHA auditado antes del
build. El workflow `qcad-spike.yml` fija ese fetch. El helper importa vcvars en un
proceso cmd local y rechaza metacaracteres en rutas; no ejecuta instrucciones de
archivos externos. `-ConfigureOnly` configura el proyecto raíz, sin acreditar
compilación de upstream. El smoke enlazado y wrapper son específicos de Windows;
la portabilidad nativa aún requiere su propio spike.

`apply_qcad_patch.py` verifica HEAD y aplica el parche con git apply --check;
si ya está aplicado, lo confirma mediante reverse --check. No restablece ni borra
cambios existentes. Parche: sustituir flags GCC -L por target_link_directories
con rutas entrecomilladas para spatialindexnavel/zlib. Fallo observado LNK1181 en
ruta con espacios. QtTools aporta UiPlugin para moc de widgets Designer; sin él
se observó «Undefined interface». No se ocultó ese error ni se omitió el target.

## Evidencia y alcance

`native/smoke/geometry.cpp` es una prueba original del motor real. Compara segmento
(0,0,7)→(3,4,7), longitud 5; círculo centro (10,20,9), radio 3, perímetro 6π.
Z preservada; tolerancia absoluta 1e-9. Baseline analítico independiente en tests.
CTest local: 2/2 suites aprobadas (30 tests Python y smoke C++). Reportes en
docs/evidence/qcad-geometry.json y qcad-build.json; no acreditan comandos completos.

Qt6 del checkout principal necesita los repositorios adicionales públicos
qcadjsapi y qtjsapi para el handler ECMAScript de la aplicación. Se identifican
y fijan commits en el reporte; no compilados/integrados en este spike. qcadjsapi
declara GPL-3.0-or-later en RScriptHandlerJs.cpp; qtjsapi MIT en LICENSE.txt.
No interpretar un qcad.exe enlazado como una UI usable sin esos handlers.

M1 permanece parcial: faltan RDocument/RDocumentInterface, transacciones/undo,
DXF mediante segundo motor, SBOM completo y build limpio remoto verificado.
La interfaz OPEN CAD aún usa el prototipo temporal. Próximo PR: fixture documental
y adaptador C++, preservando los contratos y sin ampliar el motor temporal.
